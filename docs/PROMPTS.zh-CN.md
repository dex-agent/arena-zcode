# arena-zcode:真实用例,拿来即用

🌐 [English](PROMPTS.md) | [Português (Brasil)](PROMPTS.pt-BR.md) | [Español](PROMPTS.es.md) | **中文**

下面每个用例都遵循同样的格式:什么时候用、确切的提示词、你会得到什么、要花多少。提示词
用中文写,但模型懂任何语言。成本档位:`--quick` 是 8 个代理(43 次调用),默认是 16 个
(91 次调用),`--full` 是 100 个(595 次调用,请三思)。裁判反正只花几分钱。

## 怎么让我已经收到的糟糕回答去打一架?

当模型已经答得很差、再问一遍也无济于事时。

```
$arena-zcode
```

裸调用:你最近的一次请求成为任务,你不满意的回答成为要击败的基线。结束时,盲评最终裁判
会把冠军与那个旧回答对比,如实报出比分:哪怕旧回答赢了也说。

## 怎么拿到更好的标题、邮件或发布说明?

短文案、日常赌注:用便宜档。

```
$arena-zcode --quick 为我们的定价页写标题;受众是 CFO,语气干练,最多 8 个词
$arena-zcode --quick 为这批变更写发布说明,给内部 changelog 用,语言平实
$arena-zcode --quick 给一位维护者写冷邮件,请他试用我们的工具;最多 120 词,不要行话
```

## 怎么修 bug 或不稳定的测试?

竞技场绝不碰你的文件:解决方案以 diff 形式返回,由你决定是否应用。

```
$arena-zcode --agents 16 修复 tests/test_api.py::test_retry 这个不稳定的测试;CI 上大约每 5 次挂 1 次
$arena-zcode 找出 worker/pool.py 内存泄漏的根因,并以 diff 形式提出修复
```

## 怎么在多种方案里做选择?

N 个方案进,一个幸存者出:每个选手用自己的策略卡为一个方案辩护。

```
$arena-zcode --agents 16 我们需要持久的任务存储:三节点队列服务选 Postgres、SQLite 还是 Redis;选定一个并击败另外两个
$arena-zcode --quick 我们的 CLI 用子命令还是动词式标志?给出决定和理由
```

## 怎么在有真实约束的条件下做规划?

计划也是答案:攻击/防守/裁决对它们同样有效。

```
$arena-zcode --judge-pro 规划我的发布周;每天 6 小时、单人、落地页 + 文档 + 3 个演示,周五截止
$arena-zcode --quick 从 Express 迁移到 Fastify 的零停机方案,服务有 40 个端点
```

## 怎么让我自己的设计与新想法对决?(王牌用例)

你已经有一份设计(或文档、或规范),想用替代方案来压力测试它。这是目录里最强的
一手:arena-zcode v2 正是这样设计出来的。

1. 把挑战写进一个文件,自包含(背景、约束、交付物、优先级)。
2. 把你当前的设计写进第二个文件,作为对该挑战的一份回答。
3. 让竞技场指向它们:

```
$arena-zcode --quick --seed 42 --agents 8 为 .arena/task.md 里描述的锦标赛技能做架构设计
```

并在聊天里告诉编排者 `.arena/baseline.md` 是你要击败的设计,让它用 `--baseline-file` 做
init。选手们阅读挑战、研究它指向的文件、各自做自己的设计;盲评最终裁判随后给冠军与你的
设计打分:哪怕你的设计赢了也如实报告。

这个格式经过实战验证的 task file 要素:陈述挑战、列出硬约束、按优先级排序目标、定义交
付物(工程师不用提问就能实现的程度)、指出要读的文件。经过验证的 baseline:把你的设计
写成同样的交付物。

## 怎么生成排障假设?

当你还不知道到底哪里出了问题时。

```
$arena-zcode --quick 为以下问题生成并排序根因假设:生产环境每天 09:00 出现 11 分钟的 500 尖峰,只在登录路由;图表和部署日志路径如下: ...
```

## 怎么给东西起名?

起名是锦标赛运动:短、可裁、便宜。

```
$arena-zcode --quick 为我们的开源多代理锦标赛技能起名;要在 shell 命令里读着顺口、.com 域名可用、不与商标冲突
```

## 怎么记录或解释难懂的东西?

```
$arena-zcode --quick 向新来的后端工程师解释我们的共识协议,最多 15 行,配一段文字版图示
```

## 再说一遍每个标志是干什么的?

```
--quick          8 名选手(43 次子代理调用)
--agents N       2 到 2160 之间的任意 N(策略卡各不相同)
--full           100 名选手(595 次调用):真正重要的答案
--judge-pro      裁判用会话模型(仅小组赛;最终核验仍是外部裁判)
--seed S         与上一次带 seed 的运行相同的牌和相同的对阵
--wave W         每波子代理数(默认 5)
```

活文档:`python skills/arena-zcode/bracket.py --help` 与
`node skills/arena-zcode/scripts/jev-juiz.mjs --help`。
